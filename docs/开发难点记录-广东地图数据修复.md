# 广东地图数据修复记录

## 发现的问题

用户需求是“绘制广东省地图，标定所有城市以及道路河流”。原结果虽然显示“3 个图层”，但三个图层实际重复使用 `data/data1/Guangdong.shp`，城市标签没有可靠注入，最终 PNG 只有省界面，和需求不一致。

## 主要难点与处理

1. **不能只按文件名选数据**
   - `data/data3/River.shp` 的范围在武汉，不在广东；原逻辑只按 `River.shp` 名称选择，造成跨区域数据污染。
   - 新规划器同时校验图层角色、几何类型和 bbox 空间相交关系。广东请求不会再选用武汉河流数据。

2. **本地没有广东河流线数据**
   - 本地 `Highway.shp` 可用于道路，`Guangdong.shp` 包含 21 个行政区面，但没有广东河流线数据。
   - 增加按广东边界 bbox 查询 Overpass 的远程水系兜底，仅获取带名称的河流线，并缓存到项目目录 `data_cache/`。实测返回 4,164 条 LineString，避免把 32,598 条溪流、河流和渠道一次性塞给前端。
   - 远程请求失败时返回数据源校验错误，不再使用省界文件冒充河流，也不会误报成功。

3. **图层状态和最终 PNG 曾经可能不一致**
   - `add_layer` 原来只更新状态，不保证当前画布已重绘；没有额外 `render_map/style_layer` 调用时，`map_save` 可能保存空白 PNG。
   - 保存前强制根据当前状态重绘，并记录真实 `feature_count` 与图层 bbox。

4. **显示结果的可读性与属性质量**
   - 广东数据的中文 DBF 字段存在编码问题，英文字段还把东莞写成了 `Dongyuan`。
   - 不修改原始数据，渲染层使用受控城市别名显示 21 个中文城市名，并为省界、道路、河流设置可区分的默认样式。

## 验证证据

- 规划器单元测试：拒绝武汉河流数据，普通“标注清华大学”不会误判为城市需求。
- 远程数据测试：验证 Overpass 响应会转换为 GeoJSON LineString 并写入项目缓存。
- 真实渲染验收：广东行政区 21 个面、道路 7 条线、命名河流 4,164 条线均进入状态并显示在 PNG；图例包含省界、道路、河流三项。
- 全量 Python 测试：`120 passed`。
- Django 配置检查：`System check identified no issues`。
